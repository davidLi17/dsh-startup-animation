# 工程复盘：把「启动动画」做成 DSH 插件

记录一次从「一张合成图 + 一段录屏」到「装进 DSH 每次开机都能看到的插件」的实际过程：
时间花在哪、踩了哪些坑、第一次为什么没成功。

---

## 一、时间到底花在哪

按实际耗时排序（不含来回沟通）：

| 环节 | 占比 | 说明 |
| --- | --- | --- |
| 素材分层与遮罩 | 约 50% | 从一张不透明合成图里拆出人物/鲸鱼/三条横幅/字标，反复目测+像素测量调边界 |
| 宿主接入与返工 | 约 30% | 读 DSH 源码找插件入口、装进 profile、定位素材 404、改内联 |
| 动画实现与调参 | 约 20% | 单时钟渲染、时间轴、3 秒版重排、逐帧核对 |

结论：「写动画」是最简单的部分。真正费时的是**把一张扁平的图拆成能分别出场的图层**，以及
**确认插件在真实宿主里真的能拿到资源**。

---

## 二、第一次为什么没成功

### 现象

插件装好、重启后，动画确实在跑：环形光轨、竖向扫描线、HARNESS 文字、「点击任意处跳过」全都正常。
但**7 张图层一个都没出现**，屏幕上只剩 DOM/CSS 画出来的几何元素，左上角还挂着一个图片加载失败的破图标。

### 根因

图层是用 `<img src="/plugins/dsh-startup-animation/assets/xxx.png">` 加载的，走的是宿主提供的
「包资源路由」：

```
桌面 shell  /plugins/...  →  转发给 Host（带鉴权 cookie）
Host        createRequire(manifestPath).resolve('<包>/assets/<文件>')
```

这条链路在真实桌面宿主里对这个包不生效，7 个请求全部 404。本地用 Node 手动跑同一句
`require.resolve` 是能解析到文件的，所以问题出在宿主进程里的解析上下文，而不是文件不存在。

### 为什么我的自检没抓到

我当时做了四层验证，全部通过：

1. `--dump-config` 组合层：条目确实进了插件树；
2. `node --check`：bundle 语法正确；
3. 本地 harness：动画逐帧渲染正常、播完自动撤、点击穿透；
4. 生命周期脚本：挂载 → 播放 → 移除，控制台零错误。

**第 3 层是致命的**：harness 里我用 `__DSH_STARTUP_ASSET_BASE__` 把资源指向了 Vite 的静态目录
（`/plugin-assets/`），也就是说——**我把最没把握的那一环，用替身换掉了**。于是"测试全绿"和
"真机全瞎"同时成立。

更糟的是：我其实提前看到过 404。当时 curl 了 `/plugins/dsh-startup-animation/client.js` 拿到 404，
顺手测了另外几个已装插件也 404，就判断"这是鉴权层挡的，不作数"。这个解释本身合理，但它把唯一的
预警信号消解掉了——我验证的是"是不是鉴权问题"，没有验证"我的资源路由是否可用"。

### 修法

没有继续猜路由为什么不生效，而是**让这个依赖消失**：把 7 张图层编码成 WebP 的 data URL 内联进
`lib/client.js`。内联之后加载链路里不再有路由、转发、鉴权三个可能出错的地方，client.js 能跑，
图就一定在。

代价是 bundle 从 40KB 涨到 2.75MB；换来的是这一类失败被永久消除。

## 三、坑清单

### 素材层

**1. 合成图没有 alpha**
原图 RGBA 但 alpha 全是 255。解决：亮度反算 alpha（亮=不透明），再对人物做连通域填洞得到实心剪影，
最后用多边形区域约束，避免把横幅的像素裹进人物层。

**2. Pillow 12 的 floodfill 静默失效**
`ImageDraw.floodfill` 调用不报错也不生效，导致填洞逻辑全面失效，人物层出现整块不透明的黑底。
修法：自己写低分辨率（1/4）迭代扩散求"外部区域"，再放大回来。**这类"静默成功"的库调用最容易骗过人**。

**3. 反向 smoothstep 被安全阀吃掉**
工具函数写成 `smoothstep(e0, e1, x)` 并对 `e1-e0` 做了 `max(..., 1e-6)` 保护。一旦调用时传了
`e0 > e1`（想要"从右向左渐隐"），分母变成 1e-6，整个画面被当成 1 处理——结果是一整条横带被涂黑。
修法：工具函数对反向区间显式断言，不要用 max 兜底。

**4. 近黑像素盖住背景氛围光**
人物的不透明剪影里包含大量接近纯黑的像素。当背景不是纯黑而是带蓝色氛围渐变时，这些像素会把背景
"压出"一块黑影。修法：舞台底改纯黑，氛围光改成 `mix-blend-mode: screen` 叠在最上层（只加光不减光）。

**5. 手部与白色横幅同色，无法按颜色分割**
掌心和白杠在合成图里是同一种白，没有可分割的边界。修法：去参考录屏里**白杠尚未出现**的那一帧
（1.8s/2.3s 附近）量出手掌真实轮廓——掌底边在 stage y≈344，白杠像素从 y≈350 才开始，于是能切干净。
**"用同一段视频的另一帧补出被遮挡的轮廓"** 是这次最有用的一个技巧。

**6. 开场鲸鱼直接裁胸口会带出杂物**
胸前鲸鱼被头发、领花包围，直接圆形裁片会露出一圈头发和白色领花。修法：用参考帧里那只**独立点亮**
的鲸鱼像素，按胸口鲸鱼的包围盒缩放对齐（比例只按宽度算，因为参考帧的包围盒高度被辉光撑大了）。

### 动画层

**7. 时间轴散落 setTimeout**
改成一个 rAF 驱动整条时间轴 + 纯函数 `renderFrame(t)`。暂停、拖动、定格截图、重播走同一条路径。
这是后来能"逐帧截图核对"和"重排 3 秒版"的前提。

**8. 用户要"快一点"不等于"倍速播放"**
直接按 2.4 倍缩放会把"落版"那一拍压没。正确做法是按原节奏重排分段：停留从 1.2s 压到 0.22s、
每条横幅展开从 0.45s 压到 0.28s，鲸鱼→人物→光轨的相对间隔保持不变。

### 宿主接入

**9. 误判了"启动页"在哪**
先在 app.asar 里搜到 `boot-page.ts`（白底 HARNESS + Loading plugins…），以为要改它。实际那是壳自己的
加载页，插件改不了；真正的可插入点是 ui-layout 声明的 `shell.overlay` 槽位，而 client bundle 在
`__DSH_BOOT_READY__` 门控之后、UI 首帧之前就已经就位。**先读源码确认，再动手，省掉一轮返工。**

**10. 包资源路由（第一次失败的根因）**
见第二节。教训：凡是"宿主提供的资源路由"，必须在真实宿主里用真实 URL 点一次。

**11. `pnpm add file:` 是拷贝，`link:` 才是软链接**
用 `file:` 装完后我又改了几处补丁，安装态仍是旧文件。差一点交付一个"动画播完后覆盖层不撤、
把整个应用的点击都吃掉"的版本。修法：改 `link:` 并**回读安装态**（字节数/关键字符串）确认生效。
**"我改了源码"和"运行的是我改的那份"是两件事。**

**12. 覆盖层不撤就会吞点击**
`position: fixed; inset: 0; pointer-events: auto` 的覆盖层，动画结束后只设 opacity: 0 是不够的。
必须在结束时把节点从 DOM 移除（并兜底处理渲染异常）。

**13. 首帧透明会露出下面的界面**
lead-in 一开始用 `rgba(0,0,0,0)`，等于透明，会露出应用本身。改成"主题底色铺底 + 黑幕调 opacity"两层。

### 工具链

**14. headless Chrome 的 `--screenshot` 不等图片解码**
截图拍到的是"图层还没解码"的空帧，一度让我以为图片路径错了。改用 CDP：连上浏览器、
等 `document.images` 全部 `decode()` 完成后再 `Page.captureScreenshot`。

**15. Vite 开发服务器被项目内临时目录打挂**
编辑器写文件时会在源码目录里建临时目录，chokidar 撞上 EBUSY 直接把 dev server 干掉。
修法：`server.watch.ignored` 里排除 `**/*.tmpdir/**`。

**16. PATH 里没有 python/ffmpeg**
用 DSH 自带的 Python runtime（带 numpy/Pillow）就够了；ffmpeg 缺失的情况下用参考帧的接触表代替逐帧抽帧。

## 四、决定成败的几个因素

1. **先摸清宿主的真实入口，再动手写实现。** 这次是先解析 app.asar、读 boot 门控和 slot 声明，
   才确定"插件可以做"，省掉了"改源码"的错误方向。
2. **验证要贴着真实链路。** 组合层通过、语法通过、替身渲染通过，都不能替代"真宿主里点一次"。
3. **能让依赖消失，就不要去调试它。** 资源路由不可靠 → 内联，比继续猜宿主行为更快更稳。
4. **改完要回读安装态。** 拷贝 vs 软链接、缓存、旧进程，任何一个都会让你以为改了其实没生效。
5. **UI 覆盖层要能自己收场。** 结束不移除节点、异常不兜底，代价是"整个应用点不动"。
6. **对"快一点"要重排而不是倍速。** 观感来自节奏，不来自时长。

## 五、下次再做的检查清单

- [ ] 插件入口：读源码确认门控与槽位，不靠猜
- [ ] 宿主能力：资源路由/文件读取/网络，每一样都在真宿主里点一次
- [ ] 替身测试：显式标注"这一层是替身"，并列出它替代了什么
- [ ] 安装协议：`link:` 还是会拷贝的 `file:`；改完回读安装态
- [ ] 资源：能内联就内联，消灭跨进程依赖
- [ ] 覆盖层：能跳过、能自撤、异常能收场、不吞点击
- [ ] 时间轴：单时钟 + 纯函数渲染，随时可定格截图
- [ ] 视觉验收：关键帧截图 + 与参考逐拍对照
